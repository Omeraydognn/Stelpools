# Brand — Stellar P2P TRY ⇄ USDC Escrow Gateway

A peer-to-peer fiat on/off-ramp on Stellar. People hand this interface real money,
so the brand's job is to look like infrastructure that can be trusted with it —
not like a trading floor, and not like a toy.

_Status: active · chosen 2026-09-19_

## Palette — Vault Blue

**Mood:** minimal · premium · calm · serious
**Category:** defi
**Vibe:** A private bank for on-chain. Restrained, deep, considered.

### Seeds (OKLCH)

| Role | Dark | Light |
|---|---|---|
| bg-base | `oklch(0.15 0.02 240)` | `oklch(0.98 0.008 240)` |
| bg-elevated | `oklch(0.20 0.025 240)` | `oklch(1 0 240)` |
| primary | `oklch(0.68 0.13 225)` | `oklch(0.50 0.12 225)` |
| primary-soft | `oklch(0.80 0.09 225)` | `oklch(0.65 0.08 225)` |
| fg-base | `oklch(0.95 0.015 240)` | `oklch(0.20 0.02 240)` |

Light and dark are derived from the same hue (240 surfaces, 225 primary) with
independent lightness curves — the same brand at two times of day, not an
inversion.

The full token set lives in [`web/src/index.css`](web/src/index.css) under
`:root` and `.dark`, generated by
[`.brand-preview/build.mjs`](.brand-preview/build.mjs). Re-run
`node .brand-preview/build.mjs --emit-css 1` to regenerate it.

### Contrast

Every foreground/background pair passes WCAG AA; the worst body-text ratio is
**5.30:1** (AA needs 4.5:1). The generator verifies this and nudges lightness
until it passes, so hand-edits to the tokens must be re-checked with
`node .brand-preview/build.mjs`.

One value was auto-corrected: white-on-primary came in at 2.78:1, so the
derivation flipped `--primary-foreground` to near-black (`oklch(0.12 0 225)`),
which reads at 5.30:1.

## Typography — DM Sans + DM Mono

| Role | Family |
|---|---|
| UI, headings, body | DM Sans (400/500/600/700) |
| Numbers, amounts, addresses, references | DM Mono (400/500) |

Loaded from Google Fonts in [`web/index.html`](web/index.html) with `latin-ext`
so Turkish characters (ğ Ğ ş Ş ı I İ ç Ç ö Ö ü Ü) render correctly — this was
checked visually before the pair was chosen.

DM Sans is low-contrast and soft: it reads as least "crypto exchange" of the
candidates, which suits an app whose users are ordinary people moving lira.

**Every number uses `.tnum`** (DM Mono + `tabular-nums`). Balances, TRY amounts,
USDC amounts, IBANs, swap references and countdowns must not jitter as they
update.

## Gradients

Two, both opt-in — nothing applies them globally.

* `--gradient-bg` — 135°, one hue, ±0.03 lightness. Hero and page-header depth.
  If you can clearly see it, it is too strong.
* `--gradient-accent` — primary shifted −30° toward cyan. Primary CTA and
  accent bars only.

## Tone of voice

**Plain, and short.** Users are deciding whether to send a stranger 1.000 TL.
Say what will happen: "20 USDC kilitlendi", not "İşleminiz başarıyla
gerçekleştirilmiştir". Prefer the active voice and a verb the user recognises
from their bank app.

**Never oversell safety.** The escrow is genuinely strong and the oracle is
genuinely centralised. Say both. "Oracle ödemeyi doğrulayana kadar USDC
kontratta kilitli" is honest and reassuring; "%100 güvenli" is neither.

**Turkish first, English second.** The audience is Turkish; the judges and the
docs are English. UI strings are Turkish, with an English gloss where a term is
genuinely technical (`Emanet · Escrow`). Never machine-translate a financial
term — `havale`, `IBAN`, `açıklama` are the words people actually use.

## Do / don't

* **Do** put every amount in `.tnum`, with the currency as a separate, dimmer unit.
* **Do** use `--primary` for exactly one action per screen. Two primary buttons means neither is primary.
* **Do** keep `--destructive` for money-losing actions — cancelling an offer, slashing a stake.
* **Don't** add a third gradient, or use `--gradient-accent` as a page background.
* **Don't** hardcode a hex. Every colour comes from a token so light mode keeps working.
* **Don't** use green/red as the only signal for swap state — colour-blind users need the label too.
